# Build layout

Static installable files live in `module/`: `module.prop`, `customize.sh`,
`post-fs-data.sh`, `service.sh`, `uninstall.sh`, `zt-globalctl`, and `config/`.
`build.sh` remains at the project root; libzt build and packaging scripts
live in `scripts/`. Packaging combines these
static files with `build/runtime/` and `build/webroot/` into `build/package/`.
The ZIP has `module.prop` at its root, **not** an enclosing `module/` directory.

From the module root:

```sh
git submodule update --init --recursive
./scripts/build_libzt.sh
./build.sh
(cd webui && npm run typecheck && npm run build)
./scripts/package.sh
```

All project-generated artifacts and dependencies live under `build/`:

- `libzt-source/`: upstream export with the local patch series applied.
- `libzt-cmake/arm64-v8a/<patch-key>/`, `arm64-v8a/`: CMake trees and unstripped outputs.
- `libzt-sdk/`: generated libzt header/library staging.
- `runtime/bin/`, `runtime/lib/`: stripped installable binaries.
- `webui/`: generated source mirror and Node dependencies; `npm-cache/`: npm cache.
- `webroot/`: Vite output; `package/`: complete module staging.

Do not run `npm install` in source `webui/`; the npm scripts delegate to
`tools/webui.sh`, which installs from the lockfile in `build/webui/`.
The isolated npm install ignores user `.npmrc` script policies. Development
mode mirrors `webui/src/` every second; restart it after changing config or
package metadata. Source package manifests and lockfiles remain in `webui/`.
Vendor-shipped prebuilt third-party dependencies remain vendor inputs, not
outputs generated by this project's build.

`vendor/libzt-src` is the official libzt Git submodule, pinned to a specific
commit with recursive dependencies. Clone this project using
`git clone --recurse-submodules <project-url>` or initialize as above.
Local libzt changes live in `patches/libzt/`; never edit the submodule for
normal builds. `build.sh` validates and incrementally builds patched libzt
before compiling the daemon, including its patched public headers.
An uninitialized, dirty, or wrong-revision dependency fails with a diagnostic
instead of silently building stale libraries. No source/patches enter ZIPs.

Final ZIP files are the workspace-required exception: they remain in
`../output/zerotier-libzt-global-<version>.zip`, overwriting the same version.
Installed paths remain `bin/`, `lib/`, `webroot/`; no device path changed.
Development docs, tools, tests and build caches are not included in the ZIP.
